System Architecture & Deployment Flow

Here is how code travels from your local editor to a visitor's browser when you push changes.

Phase 01

Version Control with Git & GitHub

Git tracks every modification you make. GitHub is a secure cloud drive for your Git history where our deployment robot listens for updates.

1

The Layman Analogy

Think of Git as saving snapshots in a video game before entering a new level. If anything breaks, you can travel back in time to an earlier working snapshot with a single command.

2

Why GitHub Matters Here

GitHub does more than store code. It provides an automated event listener. Every time you push code to GitHub, it can notify AWS to pull the latest version and refresh your website.

Key Rule: Keep your project clean. Never commit large binary caches or private keys to Git.
Terminal — Local Machine Setup
# 1. Initialize Git in your project folder git init # 2. Add all project files to staging git add . # 3. Create your first snapshot git commit -m "Initial release of SimpleDevOps project" # 4. Link your local project to your GitHub repository git branch -M main git remote add origin https://github.com/YOUR_USERNAME/SimpleDevOps.git # 5. Push code to GitHub git push -u origin main
Phase 02

Containerization with Docker

Docker packages your web application and its server into a standalone container, eliminating the classic problem of "it works on my machine but not on the server."

1

The Layman Analogy

Imagine packing a lunchbox that includes its own spoon, napkin, plate, and thermos. Wherever you open it — on a train, in a park, or in an office — the meal experience is 100% identical. That is a Docker container.

2

Nginx Alpine: The Lightweight Engine

We use nginx:alpine. It is a battle-tested web server packaged inside Alpine Linux that consumes only around 20MB of disk space and serves static HTML files at lightning speed.

Port 80 Explained: Port 80 is the standard port for regular HTTP web traffic. When visitors type your server's IP address, their browser automatically connects to Port 80.
Dockerfile — In Project Root
# Step 1: Use official lightweight Nginx image FROM nginx:alpine # Step 2: Copy all project files into Nginx default web directory COPY . /usr/share/nginx/html # Step 3: Tell Docker the container receives traffic on port 80 EXPOSE 80 # Step 4: Start Nginx web server in the foreground CMD ["nginx", "-g", "daemon off;"]
Phase 03

Cloud Virtual Machine with AWS EC2

Amazon Elastic Compute Cloud (EC2) provides an on-demand virtual computer in the cloud that stays powered on 24 hours a day, 7 days a week.

1

Create Free Tier Instance

Log in to the AWS Console, navigate to EC2 > Launch Instance. Select Ubuntu 24.04 LTS and choose the t2.micro (or t3.micro) size, which is eligible for the AWS Free Tier.

2

Configure Security Group (Firewall)

The Security Group acts as the virtual firewall for your server. You must allow two essential inbound rules:

  • Port 22 (SSH): For GitHub Actions and you to securely connect.
  • Port 80 (HTTP): Open to 0.0.0.0/0 so any web browser can view your site.
3

Key Pair (.pem file)

Create a new key pair named simple-devops-key.pem and download it. Store it safely — Amazon will never show you this private key again.

Terminal — Install Docker on EC2 (Run Once)
# 1. SSH into your EC2 server from your laptop chmod 400 simple-devops-key.pem ssh -i simple-devops-key.pem ubuntu@YOUR_EC2_PUBLIC_IP # 2. Update server packages and install Docker & Git sudo apt update -y sudo apt install -y docker.io git # 3. Allow ubuntu user to run Docker without sudo sudo usermod -aG docker ubuntu newgrp docker # 4. Verify Docker is running docker --version
Phase 04

Automated Deployment with GitHub Actions

GitHub Actions is your automated robot. Whenever you push code to GitHub, this script securely logs into your EC2 machine, pulls the changes, rebuilds the Docker container, and restarts it.

1

Why Build on EC2? (The Simplest Approach)

Industry setups often push images to Docker Hub or AWS ECR first. But for beginners and small projects, building directly on EC2 is significantly simpler: zero account registration, zero subscription fees, zero token expiration headaches.

2

Configure GitHub Repository Secrets

In your GitHub repository, navigate to Settings > Secrets and variables > Actions and add these three repository secrets:

  • EC2_HOST: The Public IPv4 address of your EC2 server.
  • EC2_USER: ubuntu
  • EC2_SSH_KEY: The full text inside your simple-devops-key.pem file.
Zero Downtime Principle: The workflow stops the old container and immediately spins up the new container with port mapping 80:80.
.github/workflows/deploy.yml
name: Deploy to AWS EC2 on: push: branches: - main jobs: deploy: name: Build & Run on EC2 runs-on: ubuntu-latest steps: - name: Checkout Repository uses: actions/checkout@v4 - name: Connect & Deploy on EC2 via SSH uses: appleboy/ssh-action@v1.0.3 with: host: ${{ secrets.EC2_HOST }} username: ${{ secrets.EC2_USER }} key: ${{ secrets.EC2_SSH_KEY }} script: | # 1. Clone repository if not present on server if [ ! -d "$HOME/SimpleDevOps" ]; then git clone https://github.com/${{ github.repository }}.git $HOME/SimpleDevOps fi cd $HOME/SimpleDevOps # 2. Pull latest code from GitHub main branch git reset --hard git pull origin main # 3. Build Docker image directly on EC2 docker build -t simple-devops-app . # 4. Stop and remove existing container docker stop simple-devops-app || true docker rm simple-devops-app || true # 5. Launch newly built container on port 80 docker run -d --name simple-devops-app -p 80:80 --restart unless-stopped simple-devops-app # 6. Verify container status docker ps --filter "name=simple-devops-app"
Reference

Layman DevOps Glossary

Plain English explanations of common industry jargon so you never feel lost during discussions or interviews.

Repository Git
A project folder tracked by Git that remembers the full timeline of every change, addition, and deletion.
Docker Image Docker
The frozen blueprint or recipe. It specifies the operating system, web server, and code files to package.
Docker Container Docker
A running instance of your Docker image. If the image is the recipe, the container is the cooked meal.
EC2 Instance AWS
A virtual machine running in an Amazon data center with its own dedicated IP address and internet connection.
Security Group AWS
A virtual firewall controlling which ports (such as SSH Port 22 or Web Port 80) can communicate with your server.
CI / CD Pipeline
Continuous Integration and Continuous Deployment. Code is tested and shipped automatically the moment you push to Git.
Check 1: Security Group Open on Port 80 Ensure your EC2 Security Group contains an Inbound Rule for Type: HTTP, Port Range: 80, Source: 0.0.0.0/0.
Check 2: GitHub Repository Secrets Verified Double-check that EC2_HOST contains the raw IP (without http://), EC2_USER is ubuntu, and EC2_SSH_KEY includes the complete text from -----BEGIN RSA PRIVATE KEY----- to -----END RSA PRIVATE KEY-----.
Check 3: Visit in Your Browser Once your GitHub Action finishes with a green checkmark, open your browser and navigate to http://YOUR_EC2_PUBLIC_IP to see this website live.
